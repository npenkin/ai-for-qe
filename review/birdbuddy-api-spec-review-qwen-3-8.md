# BirdBuddy API Specification Review

## Summary

The `birdbuddy-api-spec.md` document is in a rough draft state. It contains a mix of functional errors that would mislead implementers and clients, structural/markdown defects, missing sections, and stray non-technical text.

Key findings:

- **Functional errors (high impact):** the Production v3 base URL points to the QA host; the "Delete a Bird" rate-limit window is negative (`-60`); the Bird Data Model types `scientificName` as `number`; the search query parameter `size` is typed `boolean`; the `Retrieve a Bird by ID` status-code table contains three wrong error bodies (`403 Bad Request` on 400, `500 Not Found` on 500, and a 404 body on 503); the Update endpoint's JSON examples are invalid (missing comma, unquoted value, unclosed code fence).
- **Missing content:** there is no "Authentication and Authorization" section although it is explicitly referenced and `X-API-Key` is used in every endpoint; the Update endpoint has no method, no status-codes table, and an incomplete request specification; the Delete endpoint has no path; the Add endpoint's Examples section is empty.
- **Broken markup:** unclosed code spans (`/birds`, PATCH URL), an unclosed code fence in the Update example, a raw unfenced JSON block, a broken anchor `#bird-dat`, and an H1 heading ("# Try finding a non-existing bird.") inserted inside the Examples section.
- **Stray/incoherent text:** "qwerty", a literal "NEW LINE SEPARATOR" line, an empty "Hyperspace and the Future of Space Exploration" section, "omitted in the age of dinosaurs", "below the surface of the ocean", and other typos ("1newr", "nae", "vaues", "top--level", double punctuation).
- **Internal inconsistencies:** `total` contradicts empty `data` arrays in two samples; `time` values are listed as only "night" in the model but four values elsewhere; the `large` size boundary is described two different ways; error `statusCode` is a string in one example but a number everywhere else.

In total, 58 distinct issues were identified (see table below). The specification should not be published or used as a contract until these are resolved.
