# BirdBuddy API — Functional Test Scenarios

## Stage 1: Functional Requirements

| # | Name | Description | Reference |
|---|------|-------------|-----------|
| FR-AUTH-01 | API Token Authentication | All API requests must be authenticated with a personal API token sent in the `X-API-Key` header. | Authentication and Authorization |
| FR-AUTH-02 | Invalid Token Rejection | Requests with an incorrect, expired, or missing `X-API-Key` header are rejected with `401 Unauthorized` and a JSON body `{"error":"401 Unauthorized","statusCode":401}`. | Authentication and Authorization |
| FR-AUTH-03 | Per-Token Rate Limiting | Rate limits are enforced per API token. | Authentication and Authorization / Rate Limiting |
| FR-RL-01 | Search Rate Limit | Rate limit for Search for a Bird (`GET /birds`): 60 requests per 60-second window per token. | Rate Limiting |
| FR-RL-02 | Retrieve Rate Limit | Rate limit for Retrieve a Bird by ID (`GET /birds/{uuid}`): 60 requests per 60-second window per token. | Rate Limiting |
| FR-RL-03 | Add Rate Limit | Rate limit for Add a New Bird (`POST /birds`): 10 requests per 60-second window per token. | Rate Limiting |
| FR-RL-04 | Update Rate Limit | Rate limit for Update a Bird (`PATCH /birds/{uuid}`): 10 requests per 60-second window per token. | Rate Limiting |
| FR-RL-05 | Delete Rate Limit | Rate limit for Delete a Bird (`DELETE /birds/{uuid}`): 60 requests per 60-second window per token. | Rate Limiting |
| FR-RL-06 | Rate Limit Headers | Every response includes `X-RateLimit-Limit` (max requests in window), `X-RateLimit-Remaining` (requests remaining), and `X-RateLimit-Reset` (seconds until window reset) headers. | Rate Limiting |
| FR-RL-07 | Rate Limit Exceeded Response | When a client exceeds the current limit, the API returns `429 Too Many Requests` with a `Retry-After` header specifying the cooldown period in seconds, and a JSON body `{"error":"429 Too Many Requests","statusCode":429}`. | Rate Limiting |
| FR-BM-01 | UUID v4 Format | `uuid` is a UUID v4 format string. It is auto-generated by the server for every new bird added to the catalogue. | Bird Data Model |
| FR-BM-02 | Name Constraint | `name` is a string with a minimum of 1 and a maximum of 100 characters. | Bird Data Model |
| FR-BM-03 | Scientific Name Constraint | `scientificName` is a string with a minimum of 1 and a maximum of 200 characters. | Bird Data Model |
| FR-BM-04 | Description Constraint | `description` is a string with a minimum of 1 and a maximum of 5000 characters. | Bird Data Model |
| FR-BM-05 | Primary Color Enum | `primaryColor` must be one of: red, yellow, blue, orange, green, purple, pistachio, teal, indigo, magenta, scarlet, amber, grey, black, white, brown. Only 1 value allowed. | Bird Data Model |
| FR-BM-06 | Secondary Color Constraint | `secondaryColor` is an array of strings from the primary color range, with a maximum of 10 values. | Bird Data Model |
| FR-BM-07 | Flight Pattern Enum | `flightPattern` must be one of: linear, sine, circle, grounded. Only 1 value allowed. | Bird Data Model |
| FR-BM-08 | Size Enum | `size` must be one of: small, medium, large. Only 1 value allowed. | Bird Data Model |
| FR-BM-09 | Song Constraint | `song` is a string with a minimum of 1 and a maximum of 200 characters. | Bird Data Model |
| FR-BM-10 | Area Constraint | `area` is an array of location name strings with a maximum of 50 values. | Bird Data Model |
| FR-BM-11 | Time Constraint | `time` is an array of strings from {morning, afternoon, evening, night} with a maximum of 4 distinct values. | Bird Data Model |
| FR-BM-12 | Migratory Constraint | `migratory` is a boolean (`true` or `false`) or `null` (not specified). Only 1 value allowed. | Bird Data Model |
| FR-SRCH-01 | Search AND Logic | `GET /birds` returns birds matching search criteria. The search applies AND logic for all parameters except `area`. | Search for a Bird — Request specification |
| FR-SRCH-02 | Search by Name | Query parameter `name` performs an exact match on the bird's common name. | Search for a Bird — Request specification |
| FR-SRCH-03 | Search by Scientific Name | Query parameter `scientificName` performs an exact match on the bird's scientific latin name. | Search for a Bird — Request specification |
| FR-SRCH-04 | Search by Size | Query parameter `size` filters by the bird's size (small, medium, large). | Search for a Bird — Request specification |
| FR-SRCH-05 | Search by Primary Color | Query parameter `primaryColor` filters by the bird's primary color. | Search for a Bird — Request specification |
| FR-SRCH-06 | Search by Secondary Color | Query parameter `secondaryColor` accepts repeated keys for multiple values; duplicate values are ignored. | Search for a Bird — Request specification |
| FR-SRCH-07 | Search by Song | Query parameter `song` filters by the bird's song. | Search for a Bird — Request specification |
| FR-SRCH-08 | Search by Flight Pattern | Query parameter `flightPattern` filters by the bird's flight pattern (linear, sine, circle, grounded). | Search for a Bird — Request specification |
| FR-SRCH-09 | Search by Area (OR Logic) | Query parameter `area` uses keyword search to identify most probable matches. Repeated keys for multiple values; duplicate values ignored. Uses OR logic (not AND). | Search for a Bird — Request specification |
| FR-SRCH-10 | Search by Time | Query parameter `time` accepts repeated keys for multiple values from {morning, afternoon, evening, night}; duplicate values are ignored. | Search for a Bird — Request specification |
| FR-SRCH-11 | Search Limit Parameter | Query parameter `limit` accepts a number from 1 to 100. Default is 25. Limits the number of records returned. | Search for a Bird — Request specification |
| FR-SRCH-12 | Search Response Structure | Response is a JSON object with `total` (total number of matching records in catalogue) and `data` (array of bird objects up to the `limit` value). | Search for a Bird — Response Specification |
| FR-SRCH-13 | Search 200 OK | Successful search with 0 or more results returns `200 OK` with the response body per specification. | Search for a Bird — Status Codes |
| FR-SRCH-14 | Search 400 Bad Request | A query parameter with an incorrect value returns `400 Bad Request` with a detailed error message and `statusCode: 400`. | Search for a Bird — Status Codes |
| FR-SRCH-15 | Search 401 Unauthorized | Incorrect or missing `X-API-Key` header returns `401 Unauthorized`. | Search for a Bird — Status Codes |
| FR-SRCH-16 | Search 429 Too Many Requests | Rate limit exceeded returns `429 Too Many Requests`. | Search for a Bird — Status Codes |
| FR-SRCH-17 | Search 500 Internal Server Error | Server internal issues return `500 Internal Server Error`. | Search for a Bird — Status Codes |
| FR-SRCH-18 | Search 503 Service Unavailable | Server currently unable to handle the request returns `503 Service Unavailable`. | Search for a Bird — Status Codes |
| FR-RTR-01 | Retrieve by UUID | `GET /birds/{UUID}` retrieves a single bird record by the bird's UUID. | Retrieve a Bird by ID |
| FR-RTR-02 | Retrieve 200 OK | Successful retrieval returns `200 OK` with a single bird object. | Retrieve a Bird by ID — Status Codes |

| FR-RTR-07 | Retrieve 500 Internal Server Error | Server internal issues return `500 Internal Server Error`. | Retrieve a Bird by ID — Status Codes |
| FR-RTR-08 | Retrieve 503 Service Unavailable | Server currently unable to handle the request returns `503 Service Unavailable`. | Retrieve a Bird by ID — Status Codes |
| FR-ADD-01 | Add New Bird | `POST /birds` adds a new bird to the catalogue. Headers: `Content-Type: application/json`, `Accept: application/json`. | Add a New Bird |
| FR-ADD-02 | Add Required Fields | Required fields: `name`, `scientificName`, `description`, `primaryColor`, `size`. | Add a New Bird — Request Specification |

## Stage 2: Test Suites

| # | Name | Requirements | Description |
|---|------|-------------|-------------|
| TS-01 | Authentication | FR-AUTH-01, FR-AUTH-02, FR-AUTH-03 | Verifies that the API correctly enforces token-based authentication across all endpoints. Tests that a valid `X-API-Key` allows access, and that missing, incorrect, or expired tokens are rejected with `401 Unauthorized` and the specified error body. Also confirms that rate limits are tracked per token (two different tokens maintain independent counters). This is a foundational security check that gates all other API functionality. |
| TS-02 | Rate Limiting | FR-RL-01, FR-RL-02, FR-RL-03, FR-RL-04, FR-RL-05, FR-RL-06, FR-RL-07 | Validates the rate-limiting mechanism for all five endpoints. Confirms each endpoint enforces the correct request-per-window threshold (60/60 for Search, Retrieve, Delete; 10/60 for Add, Update). Verifies that every response carries the three `X-RateLimit-*` headers with correct values, that exceeding the limit produces `429` with a `Retry-After` header, and that the window resets correctly. Tests use a dedicated token to avoid interfering with other suites. |
| TS-03 | Bird Data Model Validation | FR-BM-01, FR-BM-02, FR-BM-03, FR-BM-04, FR-BM-05, FR-BM-06, FR-BM-07, FR-BM-08, FR-BM-09, FR-BM-10, FR-BM-11, FR-BM-12 | Exercises every constraint of the Bird Data Model through the `POST /birds` and `PATCH /birds/{uuid}` endpoints. For each field, tests valid boundary values (min/max lengths, valid/invalid enum values, max array sizes, distinct-value limits) and invalid values (out-of-range lengths, unknown enum entries, oversized arrays, duplicate time values). Confirms that `uuid` is auto-generated as a valid UUID v4 on creation and that `migratory` accepts `true`, `false`, and `null`. |
| TS-04 | Search for a Bird | FR-SRCH-01, FR-SRCH-02, FR-SRCH-03, FR-SRCH-04, FR-SRCH-05, FR-SRCH-06, FR-SRCH-07, FR-SRCH-08, FR-SRCH-09, FR-SRCH-10, FR-SRCH-11, FR-SRCH-12, FR-SRCH-13, FR-SRCH-14, FR-SRCH-15, FR-SRCH-16, FR-SRCH-17, FR-SRCH-18 | Comprehensive functional testing of the `GET /birds` search endpoint. Validates AND logic across parameters, exact-match behavior for `name`/`scientificName`, OR logic for `area` with keyword matching, repeated-key handling and duplicate-ignoring for `secondaryColor`/`time`/`area`, the `limit` parameter (default 25, boundary values 1 and 100), the `total` vs `data` array length distinction in the response, empty-result behavior, and all documented status codes (200, 400, 401, 429, 500, 503). |
| TS-05 | Retrieve a Bird by ID | FR-RTR-01, FR-RTR-02, FR-RTR-03, FR-RTR-04, FR-RTR-05, FR-RTR-06, FR-RTR-07, FR-RTR-08 | Tests the `GET /birds/{uuid}` endpoint. Verifies successful retrieval of an existing bird returns the full bird object with `200 OK`. Validates that malformed UUIDs yield `400`, non-existent UUIDs yield `404`, missing/invalid API keys yield `401`, and rate-limit/server errors produce `429`/`500`/`503`. Confirms the response body structure matches the Bird Data Model exactly. |
| TS-06 | Add a New Bird | FR-ADD-01, FR-ADD-02, FR-ADD-03, FR-ADD-04, FR-ADD-05, FR-ADD-06, FR-ADD-07, FR-ADD-08, FR-ADD-09, FR-ADD-10 | Tests the `POST /birds` endpoint. Verifies that a well-formed request with all required fields returns `201 Created` with a complete bird object including a server-generated UUID v4. Tests optional field handling (present and absent). Confirms duplicate rejection by common + scientific name returns `409 Conflict` with the exact error message. Validates `400` for missing required fields, `401` for auth failures, and `429`/`500`/`503` error paths. |
| TS-07 | Update a Bird | FR-UPD-01, FR-UPD-02, FR-UPD-03, FR-UPD-04, FR-UPD-05, FR-UPD-06, FR-UPD-07, FR-UPD-08, FR-UPD-09, FR-UPD-10 | Tests the `PATCH /birds/{uuid}` endpoint. Verifies that partial updates (one or several fields) are applied correctly and the response reflects the merged record. Confirms the `uuid` field is immutable. Tests that attempting to rename a bird to collide with an existing record's common + scientific names returns `409 Conflict`. Validates `400` for invalid field values, `404` for unknown UUIDs, `401` for auth failures, and `429`/`500`/`503` error paths. |
| TS-08 | Delete a Bird | FR-DEL-01, FR-DEL-02, FR-DEL-03, FR-DEL-04, FR-DEL-05, FR-DEL-06, FR-DEL-07, FR-DEL-08 | Tests the `DELETE /birds/{uuid}` endpoint. Verifies that deleting an existing bird returns `204 No Content` with an empty body, and the bird is subsequently gone (confirmed by a follow-up GET returning 404). Tests that malformed UUIDs yield `400`, non-existent UUIDs yield `404`, missing/invalid API keys yield `401`, and rate-limit/server errors produce `429`/`500`/`503`. Confirms deletion is permanent (a second delete on the same UUID returns 404). |
